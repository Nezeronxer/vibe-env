# 0009. D01: откат запушенной задачи - тоже действие «наружу»

## Контекст

План считал «Откатить» локальным `revert` и не думал, что в Push-проекте он уходит в origin. Сборка таска 03 показала два факта: revert пушится, а `.env`, закоммиченный самим агентом, мог бы попасть в main.

## Решение

В Push-проекте со «спрашивать» откат идёт `done → reverted → awaiting_outward (push_revert) → reverted`: revert-коммит уходит в origin только после «да». У PR-задачи отката нет, а кнопка говорит «закрой PR на GitHub» (`pr_no_undo`). Файл из «Копировать в копию задачи» или защищённого пути, закоммиченный агентом, вырезается до вливания. Не вырезался, или список скрытых файлов не прочитался по причине, отличной от «файла нет», - задача «Не вышло: `hidden_file_committed`», коммита нет.

## Почему

- Локальный revert без вопроса, как в плане, отвергнут: он нарушает правило, что push без разрешения запрещён. Push отката - всё равно push.
- Автоматическое закрытие PR вместо отката отвергнуто: это изменение в чужом сервисе, которое нельзя откатить, поэтому оно остаётся за человеком.
- Полагаться на то, что агент сам не коммитит `.env`, отвергнуто: коммиты делает приложение, и оно должно проверять это само.
- Продолжать при нечитаемом списке скрытых файлов отвергнуто: тогда любая ошибка чтения превращается в утечку. Остановка безопаснее.

## Последствия

- Откат запушенной задачи - два шага для человека: «Откатить», затем ответ на вопрос.
- Пока человек не ответил, локальная main уже с откатом, а origin ещё без него. Между шагами есть расхождение, и «Запушить main» его не закрывает автоматически.
- Задача с ошибкой чтения списка скрытых файлов встаёт, даже если файлов не было: ложный стоп принят как цена безопасности.
- PR-задачу откатить из приложения нельзя совсем.
