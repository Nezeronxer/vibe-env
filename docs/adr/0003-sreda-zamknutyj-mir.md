# 0003. Среда - замкнутый мир

## Контекст

В v1 ревьюер и запасной движок могли быть из другой среды, а в макете Claude, Codex и Gemini были намешаны на одном экране. Пользователь потребовал, чтобы среды не переплетались и каждая запускала только свои агенты.

## Решение

Среда - это id адаптера (`claude`, `codex`, `gemini`, `opencode`, `cursor`, `qwen`, `custom:<id>`). Все запуски задачи, роя, фабрики, ревьюера, чата и запасной модели идут только CLI этой среды. Запасное при лимите - другая модель той же среды. Наборы ставятся только в свою среду. Старые поля проекта «ревьюер» и «запасной движок» остаются в файле ради чтения старых данных, но движок их не читает. Лимиты, места для агентов и фабрика считаются на среду отдельно.

## Почему

- Запрет «в интерфейсе» отвергнут: смешать среды должно быть невозможно технически, а не просто спрятано кнопкой.
- Ревьюер из другой среды (сильная сторона v1, независимый взгляд) отвергнут: он нарушает замкнутость, а независимость даёт свежая сессия той же среды.
- Общая очередь мест на все среды отвергнута: у каждой подписки свой лимит, и Gemini не должен ждать, пока думает Claude.
- Смешанный рой «Claude + Codex + Gemini» отвергнут по той же причине. Разные модели внутри одной среды допустимы и нужны.

## Последствия

- Нельзя поручить Claude проверить работу Codex. Тот, кто хочет разнородного ревью, должен вручную перенести работу в другую среду.
- Если у среды один плохой CLI или плохой вход, её задачи стоят; в другую среду они не переезжают (статус «недоступна», «нужен вход»).
- Данные v1 с полями ревьюера и запасного движка читаются, но молча перестают действовать. Об этом одна строка в логе проекта.
- Каждой новой среде нужен свой адаптер и свой набор раскладок для наборов.
