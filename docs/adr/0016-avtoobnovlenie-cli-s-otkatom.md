# 0016. CLI сред обновляются сами, с откатом при поломке

## Контекст

Пользователь не хочет обновлять CLI руками и хочет, чтобы новые модели появлялись сами, включая Gemini и ChatGPT/Codex (G43). CLI ставили разными способами: родной установщик, npm, brew. Обновление, которое ломает CLI, оставляет человека без среды.

## Решение

`core::updates` раз в 6 часов проверяет версию каждой установленной среды. На среду три режима: «Авто» (по умолчанию), «Только сообщать», «Выкл». Автообновление ждёт, пока у среды нет идущих запусков. Обновляет родным способом CLI или тем менеджером, которым она поставлена, определённым по пути к бинарю, и никогда не использует `sudo`. После обновления `--version` должен ответить, иначе происходит откат на прежнюю версию тем же менеджером и уведомление. Обновление, прерванное выходом, продолжается при следующем запуске. Для мажорного скачка версии предусмотрена отдельная ошибка `major_jump`. Режим лежит в `updates.json`, а не в `Settings`. Если не вышло, показывается команда для ручного запуска.

## Почему

- `sudo` отвергнут окончательно: приложение не запрашивает права администратора у пользователя ради фоновой задачи. Среда, которой нужен `sudo`, получает уведомление с командой.
- Обновлять всё одним способом (например только npm) отвергнуто: CLI, поставленный иначе, получил бы второй, конфликтующий экземпляр. Способ берётся по пути к бинарю.
- Обновление при идущих запусках отвергнуто: оно подменило бы бинарь под работающей ролью.
- Откат нужен, потому что без него «Авто» опасен: сломанная версия CLI ломает среду целиком, а человек в этот момент не смотрит на экран.
- Подтверждать каждое обновление вручную отвергнуто: это вернуло бы ровно ту ручную работу, от которой пользователь хотел уйти. Для тех, кому нужна осторожность, есть «Только сообщать».
- Новая модель: роли на «последней» (G23) переходят на неё сами с всплывашкой и кнопкой «Вернуть»; только у закреплённых версий задаётся вопрос.

## Последствия

- Приложение теперь меняет программы вне собственных данных. Способ установки может не определиться (`Unknown`), и что тогда делает «Авто», в документах не описано.
- Откат опирается на то, что тот же менеджер умеет ставить прежнюю версию. Если нет, остаётся уведомление.
- Вкладки, где CLI уже запущен, продолжают на старой версии и получают полосу «перезапустить вкладку» (G54). Сессия продолжается через `--resume`/`--continue` там, где CLI это умеет.
- Идущие запуски могут откладывать обновление надолго: у постоянно занятой среды оно не придёт, пока она не освободится.
- Режим обновления лежит в `updates.json`, а не в `Settings`, поэтому ключа для него в конфиг-файле нет, пока его не добавят отдельно.
