# 0002. Одна задача - одна git-копия, вливание в main по очереди

## Контекст

Несколько агентов в одной папке мешают друг другу и человеку, а две задачи, зелёные по отдельности, могут сломать main вместе. Папка человека неприкосновенна.

## Решение

Каждая задача получает свою ветку `ns/*` и свою git-копию (worktree). Коммиты делает приложение, не агент, и перед каждым проверяет защищённые пути. В main задача попадает одним squash-коммитом. Вливание идёт строго по одному на проект: перебазирование на свежую main, при конфликте отдельная роль Интегратор, Ворота заново, продвижение main. Main продвигается без порчи папки человека: `merge --ff-only`, если он на чистой main; ожидание, если main грязная; атомарный `update-ref` вперёд, если он на другой ветке.

## Почему

- Все агенты в папке человека отвергнуты: ровно эту проблему задача и решает.
- Параллельное вливание отвергнуто: Ворота прошли на устаревшей main, поэтому красное могло оказаться в main. Очередь платит временем, зато Ворота гоняются после каждого rebase.
- Merge-коммиты и сохранение коммитов агента отвергнуты: по одной задаче нужен один коммит с читаемой историей и откатом одним `revert`.
- Коммит, сделанный самим агентом, отвергнут: приложение не может гарантировать, что `.env` не попал в коммит, если коммитит не оно.
- `reset --hard` и `push --force` по веткам человека запрещены вообще; удалять разрешено только ветки, созданные приложением.

## Последствия

- Вливание - узкое место: на проект оно одно, остальные задачи ждут. Ревью не повторяется после чистого rebase, повторяются только Ворота.
- Копии занимают диск: удаляются после финиша, у «Не вышло» живут до «Удалить» или «Повторить», готовые старше 7 дней уходят в архив.
- Грязная main у человека откладывает вливание, а не ломает его; задача вливается сама, когда правки исчезнут.
- Squash теряет промежуточные коммиты ветки. В режиме PR ветка остаётся и в main не вливается.
- Повторная задача после влитой требует, чтобы старый маркер влитой ветки ей не мешал; это отдельный тест.
