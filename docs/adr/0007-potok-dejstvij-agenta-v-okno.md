# 0007. Поток действий агента в окно (v3)

## Контекст

В v2 адаптер Claude брал из stream-json только текст и вызовы инструментов, вход сводил к одной строке, а вывод команд и диффы на экран не попадали. Живой запуск 22.10 показал: пользователь не видит, что агент делает и какие команды запускает.

## Решение

Ядро разбирает вывод CLI в события `Action(ToolAction)` и `TextDelta`. Действие приходит дважды: при старте и при результате, связь по `id` (= `tool_use_id`). Дифф строится ядром (крейт `similar`), а там, где CLI не отдаёт текст правки, берётся `git diff` копии после шага. Вывод инструмента ограничен 64 КБ, дифф - 200 КБ. Всё, что идёт в лог и в окно, проходит `scrub`. В окно события уходят склеенными не чаще раза в 50 мс на вкладку, лог хранит действия на диске, лента после перезапуска восстанавливается из лога. Старое событие `Tool{name, summary}` остаётся для совместимости.

## Почему

- Оставить строку-сводку отвергнуто: именно её пользователь назвал непрозрачной.
- Отдавать окну сырой вывод CLI отвергнуто: форматы событий у каждой среды свои, а по границам модулей их прячет адаптер. Интерфейс получает один общий вид действия.
- Не писать вывод в лог отвергнуто: после перезапуска пропала бы история хода работы.
- Писать вывод без очистки отвергнуто: вывод команды и дифф могут содержать значения секретов. `scrub` заменяет их на `${ИМЯ}` до диска и до окна.
- Слать каждое событие в окно отвергнуто: быстрый вывод тормозит окно.

## Последствия

- Лог задачи заметно растёт: до 64 КБ на событие вывода и до 200 КБ на дифф, больше обрезается с пометкой.
- Для CLI без текста правки дифф получается на уровне шага (отдельный `Edit` на файл по `git diff` копии), а не отдельной правки.
- Есть два пути в логе: новое `Action` и старое `Tool`. Пока оба нужно поддерживать.
- У CLI без частичных сообщений набор текста по словам - имитация анимацией: 30-60 мс на слово, не дольше 1,5 с на сообщение.
- Новая зависимость `similar` в ядре, хотя список был закрытым.
