## Исправлено

- Windows выбирал Unix sidecar npm вместо `.cmd`, терминал падал с Win32 error 193. Общий поиск CLI теперь учитывает PATHEXT, явные пути без расширения, уже заданное расширение и каталог `%APPDATA%/npm`.
- Windows-пути и суффиксы `.cmd`/`.exe` теряли идентификатор агента. Исправлены разбор имени и заголовок терминала.
- `capture` читал stdout и stderr последовательно: большой stderr блокировал чтение версии. Теперь каналы читаются одновременно; общий deadline действует и на трубы, удерживаемые потомком.
- ConPTY/portable-pty передавал batch-аргументы как C argv. `&` исполнялся, `%PATH%` разворачивался. Ошибка воспроизведена контрольным файлом и независимо повторена ревьюером. Фиксированный PowerShell launcher получает JSON через environment, удаляет служебную переменную перед запуском, использует batch escaping Rust std и передаёт необработанную строку через ProcessStartInfo. Проверены кавычки, Unicode, пустой аргумент, завершающий слеш и 6000 символов.
- Windows-терминал после завершения процесса оставался running: pump ждал EOF до child.wait, а ConPTY держал pipe открытым. Отдельный waiter закрывает master, reader дочитывает, pump отправляет один Exit после последнего Data. Проверены THE-END и код 17. Найденная на ревью гонка повторного attach устранена: exit публикуется только после дочитывания.
- Закрытие терминала завершает живое дерево процессов. Есть проверка, что потомок существует до close и отсутствует после.
- Внешняя Windows-консоль показывает banner установки и безопасно передаёт аргументы; метасимволы banner остаются текстом. В заголовок больше не попадает путь служебного PowerShell.
- Убрана ложная подсказка Ctrl+T у «Нового агента»; палитра на Windows/Linux показывает Ctrl вместо Cmd.
- Windows CI теперь запускает библиотечные и native workflow тесты и JavaScript selftest. Unix-specific fixtures отмечены Unix cfg. Live-проверка обновлений проверяет реально установленные CLI, а не требует Qwen на каждой машине. Браузерный F11-тест актуализирован для существующего пункта «С GitHub…» и конкретного открытого меню.

## Сборка и повторение

Windows-тесты собраны на Linux официальным rustc 1.99.1 и MSVC SDK через cargo-xwin, затем реально выполнены в Windows. Официальный rustc нужен из-за несовместимости метаданных Arch-сборки той же версии с официальным Windows rust-std. Для переносимых QA exe использовался static CRT; при линковке приложения через xwin явно добавлена libucrt.lib. Итоговая GUI-сборка сделана в dev profile с выключенными debug assertions; это локальная QA-сборка, не подписанный установщик.

На Windows с Rust, Node, Git и C++ Build Tools:

```powershell
cargo test -p nightshift-core --lib --test platform_smoke
node scripts/ui-selftest.js
cargo build -p nightshift-app
```

Локальный архив: `artifacts/Nightshift-windows-qa.zip`, SHA-256 exe - [BUILD-SHA256.txt](BUILD-SHA256.txt). Временный стенд и QMP-helper оставлены в `~/VMs/nightshift-qa` для воспроизведения. Git-история не переписывалась.
