## Главное от Anthropic
- Самопроверка, которую агент запускает сам (тесты/сборка/линтер/скриншот), важнее всего; без неё агент останавливается, когда «выглядит готовым». Жёсткие ворота - Stop-хук (exit 2) или `/goal`. Показывать доказательства, а не «готово».
- Исследовать → план → код → коммит; план пропускать, если дифф описывается одной фразой; крупное - интервью и SPEC.md, реализация в чистой сессии.
- Writer/Reviewer: свежий контекст не смещён; ревьюеру велеть сообщать только о корректности и требованиях, иначе переусложнение.
- Harness planner → generator → evaluator: отдельного скептика сделать проще, чем критичного автора; оценщик гоняет живое приложение (Playwright) с порогами. Соло 20 мин/$9 - не работает; harness ~4-6 ч/$125-200 - работает. Компоненты harness - костыли под слабости модели, с новой моделью часть убирать.
- Building effective agents: chaining, routing, parallelization (sectioning/voting), orchestrator-workers, evaluator-optimizer; начинать с простого.
- Мультиагент: +90% на исследованиях, но ×15 токенов; в коде параллелить можно меньше. Agent teams экспериментальны и не работают в `-p`; workflows работают в `-p`.
- Headless: `--json-schema`, `--max-budget-usd`, `total_cost_usd` в ответе.

## Сообщество
Ralph loop (чистый контекст, одна задача, жёсткие проверки) - для нового кода; spec-kit/Kiro - критерии приёмки до кода ценны, церемония для мелкого - шум; ruflo/claude-flow - маркетинг; Gas Town - очередь слияния с проверками; best-of-N - прирост там, где надёжный отбор (тесты + верификатор); Aider architect/editor - план и правка раздельно; без внешней обратной связи модель плохо исправляет себя (arXiv 2310.01798).

## Конвейер «Качество» (9 шагов)
1. Уточнение/спека (только для неясных задач).
2. План + критик плана, критерии приёмки (не для однострочных правок).
3. Тесты сначала, править тесты запрещено (если есть раннер).
4. Реализация одним писателем в worktree.
5. Жёсткие ворота: сборка/тесты/линтер/типы, агент не заканчивает до зелёного; потолок итераций и бюджет. **Всегда.**
6. Независимый ревьюер со свежим контекстом, JSON-вердикт, только корректность/требования; лучше другая модель/движок (выигрыш не измерен - гипотеза).
7. Запуск приложения и e2e как пользователь (для UI).
8. Доработка по ревью ≤ 2-3 кругов, потом - чистый контекст.
9. Вливание через ворота: ребейз, повтор тестов, доказательства человеку. **Всегда.**
Для рискованных задач (деньги, безопасность, данные, миграции) - best-of-N, N=2-3, отбор тестами и ревьюером.

## Рой на одной задаче
1. Best-of-N: N вариантов в своих worktree, отбор тестами + ревьюером; человек видит N карточек. Работает с headless CLI.
2. Оркестратор + рабочие по подзадачам с непересекающимися файлами; граф задач + очередь слияния.
3. Дебаты/голосование проверяющих - для поиска причин и ревью, не для записи.

## Роли (7)
Интервьюер/спека · Планировщик-критик · Автор тестов · Исполнитель · Ревьюер · Верификатор/QA · Интегратор (+ Оркестратор в рое типа 2).
