## Что должно заработать

`Engine` по `interfaces.md`: очередь с лимитом параллельности, машина состояний из спецификации, всё на потоках. Для каждой задачи:

1. `preparing`: worktree (ветка `ns/<8 символов id>-<slug заголовка>`), копирование `copy_files`, `setup_cmd`.
2. `working`: запуск исполнителя (`run_blocking`), события → лог + `EngineEvent::Log`; по завершении `commit_all`. Текст ответа заканчивается `NEEDS_HUMAN: …` (+ `OPTIONS: a | b`) → `needs_human`, `Notice::Question`; `answer()` → продолжение той же сессии с ответом. `Limit` → `paused_limit` до `resets_at` (или +30 мин), `Notice::Limit`, потом продолжение. Ошибка агента → попытка, повтор сессией.
3. `checking`: `check_cmd` в worktree; красный → исполнитель получает хвост вывода, `attempts+1`, до 3, потом `failed` + `Notice::Failed`. Нет `check_cmd` → пропуск с пометкой «тестов нет».
4. `reviewing`: ревьюер (движок `reviewer` или тот же), новая сессия, промпт = задача + дифф (до ~60 КБ) + итог тестов, ответ - JSON-вердикт; «changes» → исполнителю список замечаний, `review_rounds+1`, до 2; невалидный JSON - один повтор.
5. `merging` (мьютекс на проект): `rebase_onto` → конфликт → исполнителю «разреши конфликт» → `rebase_continue` → снова `checking`; затем `squash_to_base`. `AdvanceBlocked` → `merge_blocked`, повтор раз в минуту.
6. Финиш по `project.finish`: Local → `done`; Push/Pr при `ask_outward` → `awaiting_outward` + `Notice::Outward` (варианты «Push»/«Skip»), иначе сразу; push/PR не вышел → `done_not_pushed` с причиной. Worktree удаляется (в Pr - ветка остаётся). `Notice::Done` с итогом одной строкой.

Плюс: `cancel` (убить процесс, удалить worktree и ветку), `retry` (с чистой ветки), `remove`, `undo` (revert + push по политике), `push_base`, `pull_base`, `pause_all`, восстановление после перезапуска (`start()`: working → продолжение сессии «Continue where you stopped», остальные стадии - заново), impl `telegram::Control` (submit с подсказкой проекта по имени, status_text, digest_text за 24 часа).

Промпты исполнителя/ревьюера - константы в модуле, английские, коротко. Система исполнителя: работай только в этой папке; не пушь, не трогай remote; пиши/запускай тесты; в конце - 1-3 строки, что сделано; вопрос человеку - только если без него нельзя, последней строкой `NEEDS_HUMAN:`.

## Из брифа, дословно

> «человек даёт задачу, всё остальное делают агенты, и перепроверять этот цикл не нужно, то есть агент оповещает человека, когда это нужно»
> «чтобы удобнее было управлять агентами»
> «внедрить ветки GitHub, push, Origin»

## Критерии приёмки

- [ ] e2e (FakeAdapter + временный репо): задача доходит до `done` без вызовов извне, в main ровно один новый коммит
- [ ] e2e: красные тесты 3 раза → `failed`, main не тронута, `Notice::Failed`
- [ ] e2e: красный → исполнитель чинит → зелёный → `done`; `attempts == 1`
- [ ] e2e: `NEEDS_HUMAN` → `needs_human` с вопросом и вариантами; `answer` → та же сессия (`resume` = session id) → `done`
- [ ] e2e: ревьюер «changes» → исполнитель получает замечания → «approve» → `done`; 2 отказа → `failed`
- [ ] e2e: две параллельные задачи по разным файлам → обе в main, по коммиту на каждую; при `max_parallel=1` вторая ждёт в `queued`
- [ ] e2e: конфликт двух задач по одному файлу → исполнитель второй получает задачу разрешить конфликт (fake пишет разрешение) → `done`
- [ ] e2e: грязная main у человека → `merge_blocked`, файл человека цел; после очистки → `done`
- [ ] e2e: finish=Push + ask_outward → `awaiting_outward`; `approve_outward(yes)` → push в bare-origin; отказ origin → `done_not_pushed`
- [ ] e2e: `Limit` → `paused_limit` с `resume_at`; продолжение при наступлении времени (время подменяемо в тесте)
- [ ] e2e: `undo` → revert-коммит, статус `reverted`; `cancel` в работе → процесс остановлен, worktree удалён
