## Что должно заработать

Крейт `app` подключает всё построенное ядро (08-12) к окну и ОС: тонкие команды Tauri над `Engine`, `Chats`, `Kits`, `models`, `Store`, git; события в окно; платформенный код, которого в ядре нет по замыслу (§27): присутствие, запрет сна, терминал, тихие часы и склейка уведомлений, один экземпляр, трей. Логика команд живёт в обычных функциях модуля, которые принимают состояние приложения и тестируются без окна (шов 1: `Engine` + `FakeAdapter` + временный репозиторий), а обёртки `#[tauri::command]` только вызывают их.

**Команды v2 (имена и аргументы - из строки `app` в «Границах», аргументы с JS-стороны в camelCase).** `list_envs`, `get_catalog(env)`, `refresh_catalog(env)`, `get_limits(env)`, `list_chats(env)`, `get_chat(id, before, limit)`, `send_chat(target, msgId, text)`, `retry_chat(id, msgId)`, `remove_chat(id)`, `note(taskId, to, text)`, `answer_outward(taskId, choice)`, `resume_failed(taskId, hint, model)`, `pick_variant`, `stop_swarm`, `nudge`, `switch_model`, `freeze(on)`, `hand_off(taskId)`, `take_back(taskId)`, `start_now`, `not_a_task`, `submit_convoy`, `summary_since(at)`, `diff_file(taskId, path)`, `check_custom(id)`, `install_env(env)`, `login_env(env)`, `kits_*` (inventory, export, preview, install, enable, snapshots, rollback, check_update), `set_secret(env, name, value)`; команды v1 остаются. События v1 плюс `chat-msg`, `limits-changed`, `catalog-changed`, `frozen` (из `ChatEvent` и `EngineEvent`), событие замены настроек (G16.4: «Настройки сброшены, старые - в <файл>») и событие о запрещённых системных уведомлениях. `list_envs` отдаёт для каждой среды: id, имя, установлена ли, вошёл ли (последний известный признак), подсказку установки, счётчик ждущих человека и признак «идёт работа».

**Среды: установка, вход, доступность.** `install_env` открывает системный терминал с командой установки из `install_hint()` у человека на глазах (без вставки в оболочку строкой, без выполнения втихую); `login_env` открывает терминал с CLI среды, где вход делается её собственным способом, и после возвращения окна задачи среды продолжают сами (G17.2). Доступность сред перепроверяется при возврате к окну и раз в 5 минут (G17.3); пропавшая среда не двигает задачи в другие. `check_custom(id)` запускает свою команду с тестовым промптом в пустой временной папке и возвращает вывод и код выхода (G02.1). «Дополнительные аргументы» среды разбираются как отдельные аргументы без оболочки; неверные кавычки - ошибка с подсказкой (G16.2, G16.8). Каталог моделей обновляется при запуске приложения, раз в сутки и по `refresh_catalog`; `CatalogChanged` превращается в событие `catalog-changed` (G18.1).

**Проверка настроек (G16.2-G16.4).** `set_settings` проверяет: число вне диапазона, не число, занятая клавиша, несуществующий путь, неверные кавычки в аргументах - ошибка с понятным ключом поля, значение не применяется; изменения действуют на новые запуски, идущие доживают со своими (G16.3). Испорченный файл настроек при запуске: копия рядом, умолчания, событие в окно (G16.4).

**Трей, окно, клавиши, один экземпляр.** Всё из таска 05 остаётся; меню трея меняется на «Открыть, Новый чат, Заморозить всё / Разморозить, Выход», значок показывает `2 ▶ 1 ?` (на Linux - в подсказке); при 30 зовах в трее «30», на значке среды «9+» (G15.4, R07.3). Глобальные клавиши: новый чат из любого места ⌥⌘N / Ctrl+Alt+N (в v1 было ⌥Space; меняется в настройках), заморозить ⌥⌘. / Ctrl+Alt+. ; на Wayland глобальной клавиши нет - команда сообщает «недоступна», интерфейс показывает подсказку «назначь в композиторе `nightshift --new-chat`», и второй запуск приложения с этим флагом открывает окно уже запущенного (R10.1, одиночный экземпляр). Нет хоста значков трея (StatusNotifier) - закрытие окна сворачивает окно, а не прячет, и признак доступен интерфейсу (R10.2). «Выход» при идущих задачах - подтверждение «Идут 3 задачи. Выйти? Продолжат при следующем запуске»; выход гасит запуски, состояние на диске (R08.2).

**Уведомления (в уведомителе приложения, ядро о них не знает, §12).** Звук только у `Question`, `Failed`, `Outward`; «Готово» по умолчанию выкл., включается без звука; варианты звука «Тихий щелчок / колокольчик / без звука». Тихие часы (по умолчанию 23:00-08:00): уведомления приходят без звука и копятся, задачи не останавливаются (R15i.6). Зовы в пределах одной минуты склеиваются в одно уведомление «3 задачи ждут тебя», клик открывает первую (R15i.8). Неотвеченный зов звучит один раз (G15.4). Клик по уведомлению открывает чат задачи с раскрытым блоком «Нужен ты». Системные уведомления запрещены или службы нет - событие для полосы «Системные уведомления выключены - <как включить>»; значки и трей работают (R15i.7, R15i, «Все уведомления будут приходить именно в приложении на компьютере.»).

**Присутствие и сон (A06.1, A08.1, A08.2).** `app` определяет «человек здесь / нет» (без ввода 20 минут, экран заблокирован - где ОС это сообщает: macOS через системный счётчик простоя, Linux через idle-сервис композитора, если он есть, иначе только ночное окно) и вызывает `Engine::set_presence`. Пока агенты работают, система не засыпает (настройка «Не давать уснуть», по умолчанию вкл.; macOS - power assertion, Linux - `systemd-inhibit`); закрытая крышка и ручной сон всё равно усыпляют - после пробуждения работа продолжается. Время отсутствия для «Пока тебя не было» отсчитывается с момента, когда окно потеряло фокус или компьютер уснул; `summary_since(at)` строит сводку из логов.

**Терминал.** `open_terminal` из v1 остаётся; `hand_off` открывает системный терминал (macOS - Terminal через `open -a`; Linux - `$TERMINAL`, затем первый найденный из списка таска 05) в копии задачи с командой `interactive_resume` аргументами списком, без склейки в строку оболочки; id сессии проверяется по формату (A07). Для чата - терминал в копии чата (только чтение) с продолжением его сессии и предупреждением для ленты «правки там не сохранятся - поручи задачей» (A07.2). `take_back` вызывает движок.

**GitHub и проекты.** `github_info` возвращает ссылку на репозиторий, вход `gh`, ветки `ns/*` и статус PR задачи (G01.6). «Повторить push» у `done_not_pushed`: команды `retry` (PR-проект: повтор отправки ветки и открытия PR) и `push_base` (Push-проект) уже есть в ядре; приложение проверяет оба пути на уровне команд, а выбор между ними по `project.finish` делает интерфейс (таск 14) (G01.7). Проект, чью папку переместили или удалили, возвращается со статусом «папка не найдена: <путь>», его задачи ждут, «Указать заново» принимает новый путь с тем же репозиторием (R11.10). Единственное первое предупреждение «<Среда> работает без песочницы…» показывается один раз на среду, признак «понятно» хранится в настройках (R17i.3). Список файлов набора, установленных «только в проект», `app` вносит в «Копировать в копию задачи» проекта (результат `install` из 12).

**Наборы и секреты.** `kits_*` - тонкие обёртки над `Kits`; `set_secret` кладёт значение в связку; значения секретов не логируются и не возвращаются в окно; `Kits::env_vars` привязывается к движку как поставщик `Run.extra_env` (замыкание из 09). `Kits::recover()` вызывается при старте приложения, строка «установка <имя> прервана - откатил» уходит в окно. `diff_file(taskId, path)` отдаёт дифф одного файла с лимитом строк и признаком двоичного файла.

**Безопасность окна.** Минимальные capabilities (только нужные плагины и команды), CSP без внешних источников и без inline-скриптов, нет удалённых URL в окне, `open_path` принимает только `http(s)` и пути известных проектов и копий задач; в коде приложения нет собственных сетевых эндпоинтов, исходящее - только процессы сред, `git`/`gh` и клон набора по ссылке, которую дал человек (R13).
