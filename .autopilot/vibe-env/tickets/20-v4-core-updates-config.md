## Что должно заработать

Спека: истории 274-277, 293-294, 299; `research-updates.md` (команды, источники, «Свежесть», риски); границы `core::updates`, `core::config`.

**Обновления.** Версия установленной CLI (`--version`), последняя - npm registry / GitHub releases; способ установки по `realpath` бинаря; обновление родной командой (`claude update`, `codex update`, `qwen update`, `opencode upgrade`, `agent update`), Gemini - npm/brew; никогда `sudo`; ждёт, пока у среды нет идущих запусков (новые запуски на время обновления - в очередь); после - `--version` и `--help`, провал - откат на прежнюю версию тем же менеджером; мажорный скачок - только уведомлением. История обновлений. В `app` - расписание раз в 6 ч и при старте, событие `cli-updated{env, from, to}`, по нему `core::term` помечает вкладки этой CLI «обновлена - перезапустить» (`TermInfo.cli_version` против новой); перезапуск вкладки продолжает сессию (`--resume`/`--continue`, где CLI умеет).

**Модели.** Радар: `models.dev/api.json` с `If-None-Match` раз в 6 ч + списки CLI (`codex debug models`, `opencode models`, `agent models`) при открытии среды и раз в 24 ч. «Последняя» переходит сама (G23): Claude - алиас, Codex/opencode - первая версия списка CLI, Gemini/Qwen - сами внутри генерации, новая генерация - по кнопке. Событие `new-model{env,id,name, auto: bool}` - один раз на id. Для Codex истина - список CLI, не models.dev (снятые модели).

**Конфиг.** `~/.config/nightshift/config` (`ключ = значение`, `#` - комментарий): каждый ключ настроек; загрузка с ошибками по строкам (неизвестный ключ / неверное значение → ошибка + умолчание); запись ключа с сохранением комментариев и порядка; слежение за файлом (опрос mtime раз в 1 с - без новых зависимостей) → событие `config-changed{errors}`; файла нет - создаётся с закомментированными умолчаниями по `config_open`. Экран настроек и конфиг меняют одно и то же (`Settings`).

## Из брифа, дословно

> «когда выходила новая модель, автоматически обновлялся, и все модели автоматически обновлялись, включая GMI, включая ChatGPT» (G43)
> «Если вышло обновление какого-то терминального CLI, то ты его берёшь автоматически, приходит обновление, и пользователь должен перезапустить именно окно с терминалом» (G54)
> «приложение можно было полностью кастомизировать конфигами, но также настройками можно вручную» (G51)

## Критерии приёмки

1. Тесты на фикстурах вывода CLI и ответов npm/models.dev: версия, способ установки по пути (npm/brew/native), команда обновления; `sudo` нигде.
2. Обновление при идущем запуске среды ждёт; провал `--version` после обновления → откат (фейковый установщик в тесте).
3. Новая модель в фикстуре models.dev и списке CLI → одно событие `new-model`; повтор опроса (304/тот же id) - ни одного.
4. Codex: модель есть в models.dev, но нет в `codex debug models` - не предлагается.
5. Конфиг: круг «прочитать → изменить ключ → записать» сохраняет комментарии и порядок; `font-size = big` → ошибка «строка N», остальное применено.
6. Живой прогон (`#[ignore]`): `check` для установленных на маке claude, opencode, qwen - версии в отчёт; ничего не обновлять.
