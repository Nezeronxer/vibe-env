## Что должно заработать

Фундамент v2 под всеми остальными тасками: типы, хранилище, адаптеры и каталог моделей. После таска движок (09) может запускать роли с моделью и версией, получать лимиты и стоимость из вывода сред, а интерфейс и чат - читать чаты, каталог и лимиты с диска. Движок в этом таске не меняется по поведению.

**Типы.** В `core::model` добавляется весь блок «Типы, которые добавляются» из спецификации (`EnvId`, `ModelChoice`, `ModelFamily`, `Catalog`, `ResolvedModel`, `RoleKind`, `Step`, `StepState`, `QualityPlan`, `SwarmSpec`, `RoleRun`, `StartWhen`, `OutwardChoice`, `LimitWindow`, `EnvLimits`, `EnvSettings`, `Chat`, `ChatMsg`, `Who`) и поля `Task`, `Project`, `Settings`, `LogEvent` из комментария под блоком; `Status` получает один новый вариант `HandedOff`. Любое новое поле читается с умолчанием (`#[serde(default)]`), файл v1 из тасков 01-03 открывается без миграции (R01); умолчания настроек - таблица §29 (G16.1: приложение работает, ни разу не открыв настройки). `Settings.telegram` остаётся в файле, но никем не читается; `Project.reviewer` и `Project.fallback_agent` остаются в файле и не читаются (§15, история 80). `Settings.max_parallel` по умолчанию 3 и означает «агентов на среду» (R19i.5; поведение - в 09). Добавление вариантов в перечисления ломает сопоставления по всему репозиторию: этот таск чинит их везде (`app/`, `ui/` не трогать, если там JSON-строки), а в `core/src/engine/` - только минимум, чтобы компилировалось, с пометкой в отчёте (поведение движка правит 09). Из `core/Cargo.toml` убирается `reqwest` (Telegram снят, §33, R13: ядро не ходит в сеть сам), добавляются `zip` и `sha2` (наборы, 12; чтобы 12 не правил манифест параллельно с 09) - с одной строкой «почему» в отчёте.

**Хранилище.** `Store` получает чаты (`chats(env)`, `chat`, `upsert_chat`, `remove_chat`), сообщения (`append_chat_msg` возвращает `Ok(false)`, если такой id уже есть - ключ идемпотентности, G20.8; `read_chat(id, before, limit)` отдаёт последние записи страницами, G20.11), снимок каталога и снимок лимитов (`catalog.json`, `limits.json`). Лента чата - файл на чат (`chats/<chat>.jsonl`), запись через временный файл и rename, как остальное. Испорченный файл настроек не роняет приложение: рядом сохраняется копия, берутся умолчания, а интерфейс может узнать, что это произошло и где копия (G16.4; имя метода выбирает исполнитель и записывает в `interfaces.md`).

**Адаптеры.** `Run` получает `model`, `read_only`, `extra_env`, `json_schema` и - недостающее в спецификации - `max_budget_usd: Option<f64>` (§30 говорит, что потолок передаётся флагом, но поля для него в `Run` нет; зафиксировать в `interfaces.md`). `Role` расширяется до `RoleKind`. `AgentEvent` получает `Usage(Vec<LimitWindow>)`, `Cost(f64)`, `ModelRejected(String)`, `AuthRequired(String)`. `Adapter` получает `models()`, `builtin_models()`, `interactive_resume(session, cwd)`, `read_only_native()`, `reports_cost()`, `install_hint()`, `sandbox_info()` (все - с поведением по умолчанию, чтобы своя команда и старые тесты не менялись). Что делает каждая среда - только то, что подтверждено `research-clis.md` или спецификацией; всё остальное помечено `// unverified` и не выдаётся за факт:
- флаг модели: Claude `--model`, Codex `-m`, Gemini `-m`, opencode `-m provider/model`, Cursor `--model`, Qwen `-m`; нет модели - нет флага;
- чтение (история 133): Claude `--permission-mode plan`, Codex `--sandbox read-only`, Gemini `--approval-mode=plan`, Cursor `--mode ask` (`read_only_native() == true`); у opencode, Qwen и своей команды флага нет (`false`) - движок будет запускать такие роли в выбрасываемой копии;
- схема ответа: Claude `--json-schema`, Codex `--output-schema`; у остальных `json_schema` игнорируется (JSON ищет движок);
- Claude: событие `rate_limit_event` превращается в `Usage` по структуре `unifiedWindows.five_hour` / `seven_day` (`utilization` - доля 0..1, переводится в проценты; `resetsAt` - Unix-секунды), статус не `allowed` и ошибка категории `rate_limit` - в `Limit`; стоимость итога запуска - в `Cost`; потолок бюджета - `--max-budget-usd`; `reports_cost() == true` только у Claude;
- распознавание входа (`AuthRequired`), отказа модели (`ModelRejected`) и лимита у остальных сред - по тексту, на сохранённых образцах; где образца нет, правило помечено `// unverified` (список «Открытых мест» в спецификации); время сброса из текста, иначе `resets_at: None`;
- `interactive_resume`: Claude `claude --resume <id>`, Gemini `gemini --resume <id>`, Qwen `qwen --resume <id>`, Cursor `agent --resume <id>`, opencode `opencode -s <id>` (работа в интерактивном режиме не подтверждена); Codex и своя команда без шаблона продолжения - `None` (A07, A07.1). Команда возвращается списком аргументов, id сессии проверяется по формату до подстановки;
- `extra_env` попадает в окружение запуска; дополнительные аргументы среды (`EnvSettings.extra_args`) идут отдельными аргументами, без оболочки;
- `install_hint`: команды установки не сверены (Открытые места) - берутся из макета (`mockup/mockup.js`: Cursor `curl https://cursor.com/install -fsS | bash`, Qwen `npm install -g @qwen-code/qwen-code`; остальные - из строки `install` макета), с пометкой «не сверено»;
- `sandbox_info()`: что среда делает сама - песочница (включена / нет защиты), доступ к сети, файлы вне копии; у Claude из `guarded()` и `network_note()` таска 02, у остальных «нет защиты» (история 219). Структура `SandboxInfo` в спецификации не описана - минимальная по историям 201 и 219, записать в `interfaces.md`;
- `FakeAdapter`: сценарии по роли и варианту (в рое порядок запусков недетерминирован), `with_models`, `FakeStep::{Usage, Cost, RejectModel, Auth}`; `calls()` показывает модель и флаг чтения каждого запуска.

Ранее принятая на живом выводе работа таска 02 не ломается: регрессионные тесты 02 (в том числе `$(touch PWNED)` в своей команде) остаются зелёными.

**Каталог моделей `core::models`.** Источники: `models()` адаптера (Codex `codex debug models`, opencode `opencode models [provider]`, Cursor `--list-models` - разбор на сохранённых образцах), иначе последний удачный снимок из `Store`, иначе `builtin_models()`; везде добавляются «Своя модель» (`EnvSettings.custom_models`) и «Как в CLI по умолчанию» (без флага). Для Claude, Gemini и Qwen команды списка нет - встроенный список: семейства, описания и порядок «от сильной к быстрой»; номера версий вносятся только из установленной CLI или документации вендора, а где их проверить нечем - семейство остаётся только с «последней» (не выдумывать номера). `resolve` превращает выбор в аргумент CLI («последняя» у Claude - алиас семейства `opus`/`sonnet`/`fable`, у остальных - первая версия семейства; закреплённая - точное имя) и в подпись, с пометками `Newer` («есть новее: 5.1», тихая), `Replaced` (версию сняли - ближайшая: следующая новее того же семейства, иначе последняя семейства; закрепление переносится только явным действием), `Rejected`. `next_on_reject` - цепочка повтора при отказе CLI: последняя того же семейства, затем без флага. `stronger_than` - первая модель списка среды, отличная от текущей (список упорядочен от сильной к быстрой).

**git.** Добавляются функции из «Границ»: `create_readonly_copy` / `refresh_readonly_copy` (копия без ветки на свежей base; неотслеживаемое в ней удаляется - только в копиях приложения), `diff_file` (с `max_lines`; двоичный файл - признак и размер), `changed_paths`, `restore_paths`, `ff_branch` (только вперёд), `clone_shallow` (только `https://`, `ssh://`, `git@`, локальный путь; `ext::` и `--upload-pack` отвергаются; клон мелкий и во временную папку). Прежние функции и их правила (никакого `--force`, `reset --hard` только в копиях приложения, удаляются только ветки `ns/*`) не меняются.
