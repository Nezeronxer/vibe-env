## Что должно заработать

README на английском (+ `README.ru.md`): что это одной фразой, скриншот главного экрана (снят с запущенного приложения или dev-mock, лежит в `docs/`), как работает цикл (схема из 6 шагов), сравнение с аналогами «чем отличается» (по `.autopilot/vibe-env/research.md` - только факты оттуда), поддерживаемые среды с пометкой «проверено» / «по документации» (проверено живьём - Claude Code, opencode, Qwen Code; Codex, Gemini CLI, Cursor - только по документации, `research-clis.md` и «Открытые места»), лимиты, «Перенос среды», безопасность (что агенты могут и не могут, песочница, среды без технических запретов), Telegram в README не упоминается (бот снят), как добавить свою среду (файл-адаптер / своя команда), установка и сборка.

**Установка одной командой.** `scripts/install.sh`: определяет ОС и платформу, берёт последний релиз со страницы Releases, на macOS монтирует `.dmg`, копирует приложение в `/Applications` и снимает карантин (`xattr -dr com.apple.quarantine`), на Linux кладёт `.AppImage` в `~/.local/bin` (для `.deb` печатает команду `dpkg -i`); репозиторий и имя продукта берутся из одной переменной в начале файла, пока публикации нет, значение - ASSUMPTION и помечено заглушкой (публикация только после явного «да», R02). Скрипт ничего не запускает при проверке: проверяется `sh -n` / `shellcheck`, если он есть. README показывает одну строку установки, а также установку вручную из Releases (`.dmg` / `.AppImage` / `.deb`), зависимости Linux (webkit2gtk и appindicator) и сборку из исходников.

**Подпись macOS (R20i.2).** Подписи нет: нужен платный Apple Developer аккаунт пользователя («Открытые места»). До тех пор README объясняет `xattr -dr com.apple.quarantine <приложение>`. В `release.yml` подпись и нотаризация - заглушка: шаги и секреты описаны комментарием и включаются только при заданных секретах репозитория (имена переменных - по документации Tauri 2 и `tauri-action`, сверить перед записью), без секретов сборка идёт неподписанной и не падает.

**Знаки и товарные знаки (G21.2).** В README строка: «Товарные знаки принадлежат владельцам и используются только для обозначения совместимых продуктов.» Файл `mockup/icons/SOURCES.md` (источник и условия каждого знака; он же в `ui/icons/SOURCES.md` после таска 14) переносится в документацию как `docs/icons-sources.md`, README ссылается на него. «Условия на знаки (theSVG, Simple Icons)» - из «Открытых мест» спецификации: перепроверить по ссылкам из файла перед публикацией и записать результат; если условия не подтверждаются, знак отметить в отчёте как блокирующий публикацию.

**Сборка и CI.** `.github/workflows/release.yml` - сборка по тегу `v*` на `macos-latest` и `ubuntu-22.04` через `tauri-apps/tauri-action` (черновик релиза; цели `dmg`, `appimage`, `deb`); `.github/workflows/ci.yml` - `cargo test -p nightshift-core` на обеих ОС на push/PR, плюс `cargo build -p nightshift-app` и проверка `ui/selftest.html`, если это можно запустить без окна. Версии actions - закреплённые теги. `LICENSE` - MIT (ASSUMPTION, автор - Nezeronxer); `CONTRIBUTING.md` - коротко; имя «Nightshift» - ASSUMPTION и меняется заменой одной строки в конфиге сборки и словаре (R21, история 222).

**Подготовка к аудиту и публикации (G04, R02.1).** Сам аудит безопасности проводится после сборки отдельным шагом (раздел «Аудит безопасности» спецификации); здесь готовится почва: `docs/security.md` - карта границ (что агенты могут и не могут, права ролей, песочница по средам, где лежат секреты, что уходит наружу и что нет, Tauri capabilities и CSP) по таблице аудита, с местом под отчёт аудита; `.gitleaks.toml`, если нужны исключения для тестовых образцов; в README - чек-лист публикации: аудит закрыт, `gitleaks` по всей истории чист, README и LICENSE на месте, CI собирается - иначе публикации нет и причина в отчёте. **Ничего не публиковать и не пушить.** Только файлы.
