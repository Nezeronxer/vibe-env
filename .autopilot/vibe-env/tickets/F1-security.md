## Что должно заработать

Аудит безопасности 22.10 (5 независимых проверяющих, каждая находка подтверждена свежим агентом) нашёл четыре дыры. Модель угроз: атакующий - автор чужого набора или содержимое репозитория, над которым работает агент; пользователь и его машина доверенные. Общий принцип починки - **разрешительный список вместо запретительного**: перечнем опасного дыры закрываются по одной, и следующий проверяющий находит ещё одну (так уже было с переменными окружения).

## Критерии приёмки

1. **Переменные набора - разрешительный список** (`core/src/kits/secrets.rs:60`). Сейчас запрет классами пропускает `CLAUDE_ENV_FILE`, `CLAUDE_CODE_SHELL_PREFIX` (Claude Code выполняет их перед каждой командой Bash), `OPENCODE_CONFIG`/`OPENCODE_CONFIG_CONTENT` (MCP-команда, подмена baseURL), `CODE_ASSIST_ENDPOINT` (Gemini шлёт OAuth-токен на этот адрес). Условие: из набора задаётся только имя, похожее на секрет, - `*_API_KEY`, `*_KEY`, `*_TOKEN`, `*_SECRET`, `*_PASSWORD` (те же признаки, что §26 использует для поиска секретов при экспорте), и при этом не попадающее под уже действующие запреты классами (D04). Всё остальное - `bad_name`. Тест: каждое из названных четырёх имён отклоняется; `OPENAI_API_KEY`, `GITHUB_TOKEN` принимаются. Обнови строку D04 в `spec.md` §11 не ты - оркестратор; верни итоговое правило в `INTERFACES`.
2. **Настройки набора, меняющие адрес или авторизацию провайдера, не ставятся молча** (`core/src/kits/units.rs:193` `runs_something`, `units.rs:439, 486, 536`, установка `kits/mod.rs:1068-1082`). Сейчас opencode `provider.*.options.baseURL`/`apiKey`/`{env:…}` и Codex `model_provider`, `[model_providers.*]` (`base_url`, `env_key`, `requires_openai_auth`), `openai_base_url`, `chatgpt_base_url`, `profiles` проходят как обычная настройка, без галочки, - и CLI шлёт ключ пользователя, код и промпты на сервер атакующего. Условие: у каждой среды разрешительный список безопасных ключей настроек верхнего уровня (модель, тема, интерфейсные ключи - что реально безопасно в раскладке среды); всё прочее получает `held = Some(HeldKind::Command)` и выключено до галочки, как хук, с пометкой в плане. Тест: opencode.json с `provider.x.options.baseURL` и config.toml с `model_provider` + `[model_providers.x] base_url` дают held, а не запись.
3. **Скиллы и субагенты из чужого набора с исполняемым содержимым выключены до галочки** (`core/src/kits/units.rs:274`, `cut()` для `Group::Skills` и `Group::Agents`). Сейчас скилл или субагент без отдельного файла-скрипта ставится сразу, хотя в самом `.md` бывает исполняемое: `hooks`/`mcpServers`/`permissionMode`/`allowed-tools`/`tools` во frontmatter, строки ``!`команда` `` в теле. Условие: такие скиллы и субагенты получают held (вид `ScriptedSkill` или новый для агентов) и показываются в плане целиком, как хуки. Если по раскладке надёжно определить нельзя - держать выключенными все скиллы и субагенты чужого набора. Тест на каждый признак.
4. **«Защищённые пути» работают** (`core/src/git.rs:274` `add_all`, `core/src/engine/flow.rs:648`, `core/src/model.rs:664`, `core/src/agent/adapters/claude.rs:36-49`). Сейчас `Settings.protected_paths` нигде не читается: если агент (по инструкции из репозитория) создаст `.env`, ключ или копию `~/.ssh/id_*`, движок закоммитит это, вольёт и запушит от имени приложения, вне песочницы. Условие: при включённом флаге после `git add -A` пути, для которых `scrub::is_secret_file(rel)` истинно (`.env*`, `*.pem`, `*.key`, `id_rsa*`/`id_ed25519*`/`id_ecdsa*`, `.netrc`, `credentials*`), снимаются с индекса; перед вливанием, push и PR (рядом с проверкой hidden в `flow.rs:648`) коммиты `base..HEAD` проверяются на такие пути, и при совпадении - отказ с понятной строкой в ленте; `.env`, нужный тестам в копии задачи, по-прежнему копируется и не коммитится. В `--settings` Claude добавлен deny `Read(~/.ssh/**)` (только `~/.ssh`, не `*.pem` - иначе ломается TLS). Тест: агент-заглушка создаёт `.env` и `fixtures/id_ed25519` - в коммите задачи их нет, лента говорит почему.

Общие правила ремонта: причина каждой дыры одной строкой в `CONCERNS`, таймауты и проверки в тестах не ослабляются, полный `cargo test --workspace`, `cargo clippy --workspace --all-targets -- -D warnings`, `node scripts/ui-selftest.js` - зелёные.
