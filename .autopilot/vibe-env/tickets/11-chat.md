## Что должно заработать

Модуль `core::chat` поверх движка делает чат главной поверхностью среды: человек пишет модели как в обычном чате, спрашивает про проект и получает ответ, а на «Сделай…» сообщение само становится задачей в той же ленте. Чат = среда + проект + сессия CLI. Всё внутри чата идёт только через CLI своей среды (G22).

**Отправка (`Chats::send(target, msg_id, text)`).** `target` - существующий чат или `New { env, project_id }` (проект нового чата - тот, что был открыт; после первого сообщения не меняется; заголовок чата - начало первого сообщения). Сообщение сохраняется по `msg_id`, который создаёт окно: повторная отправка с тем же id игнорируется, и двойной Enter или клик плюс Enter дают одно сообщение и одну задачу (G20.8). Пустое сообщение не принимается; черновики живут в интерфейсе (G20.7), но модуль не принимает пустого и не теряет набранное при ошибке.

**Вопрос или задача (два слоя, §19).** Первый слой - быстрый и предсказуемый: сообщение начинается с глагола-поручения из словаря (ru: сделай, добавь, почини, исправь, перепиши, напиши, убери, переведи, обнови, переименуй, удали…; en: make, add, fix, implement, refactor, rename, remove, update…) - сразу создаётся задача через `Engine::submit` с `chat_id`, и под сообщением строка «Это задача. Переписал в промпт и запустил шаги качества.» с возможностью показать промпт. Второй слой - модель: по системному правилу чат-роли ответ, если просьба меняет код, заканчивается строкой `NS_TASK: <заголовок>`; тогда задача создаётся из сообщения человека тем же способом, а сам признак в ленте не показывается (принимается только из конца ответа). Параметры задачи (Качество, Рой, «Когда начать», модель) берутся из последнего выбора человека для этой среды (`EnvSettings.last_quality`, `last_swarm`, `last_start`, `default_model`). Ошибку распознавания исправляет `not_a_task` движка («это был вопрос»): пока задача не дошла до шага «Код», она отменяется, а сообщение возвращается чату как вопрос; позже работает обычная отмена.

**Ответ модели.** Каждое сообщение - запуск роли `Chat` строго только для чтения в копии чата (`create_readonly_copy` на свежей main без ветки, перед сообщением `refresh_readonly_copy`); если CLI без запрета записи что-то записал, запись выбрасывается перед следующим сообщением. Папка проекта человека и main после вопроса не меняются (G20.5, G07.1). Следующее сообщение продолжает ту же сессию CLI; сессия недоступна (CLI её не нашёл) - новая сессия с пересказом последних 20 сообщений и строкой «начал новую сессию» (G20.6). Модель ответа подписывается как «<Среда> · <Модель версия>». Не ответил (CLI упал, нет сети, не вошёл) - в ленте «Не ответил: <причина>», `retry(id, msg_id)` повторяет; лимит среды исчерпан - «отвечу после 19:00», и сообщение уходит само после сброса (G20.9).

**Сообщения во время задачи (G05).** Сообщение в чате, где есть идущая задача, превращается в заметку `Engine::note` («передам исполнителю» → «передано в 14:15»); если задача ждёт ответа на вопрос - сообщение и есть ответ (`answer`); «своими словами» на вопрос работает так же (G05.1). Задача успела влиться раньше - заметка «не передана: задача уже влита», и сообщение обрабатывается как обычное сообщение чата, то есть как вопрос или новая задача по двум слоям выше (G05.2). Какой именно задаче чата адресована заметка, когда их несколько, спецификация не уточняет: брать последнюю созданную из ещё не законченных, ответ на вопрос - ту, что ждёт ответа; правило записать в `interfaces.md`.

**Список и жизнь чатов (`list(env)`).** Чаты по проектам; у пункта - состояние самой срочной задачи чата в порядке «ждёт тебя > не вышло > работает > в очереди > готово > просто разговор»; чат без задач - значок разговора и начало последнего ответа; пустая среда - пустой список. В список входят чаты-поручения (`convoy`) и записи роя: по одной на задачу среды с `Task.swarm` (чат роя строит таск 10 из событий лога задачи). Лента грузит последние 200 записей, старше - постранично (`messages(id, before, limit)`); чаты без движения 7 дней получают `archived`, из архива возвращаются первым же сообщением (G20.11). `remove(id)` отказывает, пока в чате идёт задача («сначала отмени задачу»); готовые задачи чата остаются в истории проекта (G20.12). `subscribe()` отдаёт `ChatEvent` для окна. Чтобы приложение могло открыть чат в терминале (A07.2), модуль отдаёт копию чата и id его сессии; форма записывается в `interfaces.md`.
