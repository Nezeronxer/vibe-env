## Что должно заработать

`core::kits` переносит настройки среды между машинами и людьми: скиллы, правила, хуки, MCP-серверы, субагентов и настройки одной среды. Ничего импортировать не нужно, чтобы среда работала с моими скиллами и хуками: приложение запускает мою CLI, и она читает свои каталоги как есть (G25, история 204) - модуль только показывает, что там лежит (`inventory`: счётчики и списки по группам для среды и области «все проекты / проект»), и умеет упаковывать и ставить наборы. Модуль не знает про движок и интерфейс; работает с файлами CLI и каталогом данных приложения (`Kits::new(home, data_dir)`), поэтому тестируется на временном «домашнем» каталоге (шов 4).

**Раскладка сред (§26).** Таблица каталогов, правил, хуков, MCP, субагентов и скиллов каждой среды - из спецификации (Claude Code, Codex, Gemini, opencode, Qwen). Группа, помеченная в таблице «не подтв.», неактивна с подписью «раскладка <среды> не сверена»: Cursor целиком, скиллы Codex, Gemini и Qwen, MCP у Claude и opencode, файлы субагентов Codex. Исполнитель не домысливает раскладку; сверить её с установленной CLI можно только там, где CLI есть на машине (Claude, opencode, Qwen), а подтверждённое отметить в `interfaces.md`.

**Формат набора.** Папка с `kit.json` (формат, среда, версия приложения, список файлов с `sha256`, нужные переменные окружения) и файлами в раскладке среды. Набор записывает свою среду.

**Экспорт (`export`).** Группы выбираются галочками (Скиллы, Правила, Хуки, MCP-серверы, Субагенты, Настройки; пустая группа неактивна) в папку, zip или локальный git-репозиторий (отправить его наружу - действие человека, модуль только инициализирует и коммитит). Секреты не попадают в набор: значения ключей с именами вида `*TOKEN*`, `*KEY*`, `*SECRET*`, `*PASSWORD*` и строки, похожие на токены (правила как у gitleaks, своя таблица шаблонов в модуле), заменяются на `${ИМЯ}`, имена переменных попадают в `kit.json`; абсолютные пути домашнего каталога переписываются в `~`.

**Импорт (`preview` → `install`).** Источник - ссылка на репозиторий (клон `git::clone_shallow` из 08, только разрешённые схемы), папка или zip. `preview` ничего не меняет на диске и возвращает план: куда ставить (для всех проектов - каталог среды; только в проект), что добавится, что заменится (старое уйдёт в снимок, доступна «разница»), что уже есть. Набор чужой среды не ставится (G25.6, G22): отказ «Это набор Codex. В Claude Code он не ставится: у каждой среды свои скиллы и правила» вместе с данными для «Открыть в Codex». Плохой набор отвергается с причиной и без единой записи на диск: не набор, битый zip, путь из архива за пределы папки (проверка каждого пути до распаковки; системный `unzip` её не даёт, поэтому крейт `zip`), симлинк, файл больше 10 МБ, набор больше 50 МБ, клон не удался (G25.8). Установка пишет журнал, делает снимок всех файлов, которые изменятся, пишет во временные файлы и переименовывает; прервалась (выход, сбой диска) - `recover()` при следующем запуске откатывает по снимку и сообщает «установка <имя> прервана - откатил» (G25.9). `rollback(SnapshotId)` возвращает файлы и удаляет добавленное; список снимков с датой и источником - `snapshots(env)`. Установка идёт, пока работают задачи: установленное действует на новые запуски, идущие доживают со своим (G25.12).

**Хуки, MCP и скрипты.** Хуки и MCP-серверы с командой запуска и скиллы со скриптами показываются целиком (событие, команда и текст скрипта) и после установки выключены, пока человек не включит каждый (`enable_item`). Выключенный хук или MCP не пишется в файлы CLI вовсе (не у всех CLI есть флаг «выключен»), а хранится в снимке набора до включения, откуда и ставится позже без повторного импорта (G25.4). Скилл со скриптами помечается «содержит скрипты».

**Секреты (`set_secret`, `env_vars`).** Недостающие переменные вводит человек: значения идут в системную связку ключей (крейт `keyring`, служба `nightshift`, имя `<среда>/<переменная>`; без связки - файл с правами 0600 и предупреждение для интерфейса). Значений нет ни в `kit.json`, ни в файлах CLI, ни в логах, ни в `state.json`, ни в промптах (R17i.2). `env_vars(env)` отдаёт пары для `Run.extra_env` запусков этой среды; для запуска CLI вручную в обычном терминале этих переменных нет - интерфейс подсказывает добавить их в профиль оболочки (G25.3).

**Только в проект (G25.10).** Файлы ставятся в папку проекта (не коммитятся) а их пути возвращаются в результате списком для «Копировать в копию задачи» проекта, чтобы агенты в копиях их видели (модуль `Store` не держит, список в проект вносит `app` в таске 13); результат содержит признак «файлы набора в проекте не закоммичены».

**Обновление (`check_update`).** Набор, поставленный по ссылке, помнит источник и коммит; проверка показывает тот же план «что изменится»; само ничего не ставится, новые и изменённые хуки снова выключены (G25.7). Первый запуск: `inventory` отвечает на «Найдены твои скиллы и правила (<каталог>) - подключены» (G25.11). Сети у модуля нет, кроме клона по ссылке, которую дал человек (R13).

## Критерии приёмки

- [ ] Экспорт во временный «дом» среды с секретами: ключи с именами `*TOKEN*`/`*KEY*`/`*SECRET*`/`*PASSWORD*` и токеноподобные строки заменены на `${ИМЯ}`, в готовом наборе значений нет (поиск по всем файлам), пути домашнего каталога записаны как `~`, пустая группа неактивна
- [ ] Три вида получателя экспорта работают: папка, zip, локальный git-репозиторий (инициализирован и закоммичен, не отправлен)
- [ ] `preview` ничего не пишет на диск (сравнение дерева до и после); план содержит «добавится / заменится (с разницей) / уже есть» и выбор «для всех проектов / в проект»
- [ ] Набор Codex в Claude Code отвергается с текстом отказа и данными для «Открыть в Codex»; группы «не подтв.» неактивны с подписью про несверенную раскладку
- [ ] Отказы без записи на диск: не набор, битый zip, путь за пределы папки (zip slip), симлинк, файл больше 10 МБ, набор больше 50 МБ, клон по `ext::…` или недоступной ссылке
- [ ] После `install` хук, MCP и скилл со скриптами выключены и в файлах CLI их нет; после `enable_item` они ставятся из снимка без повторного импорта; хук показывается целиком вместе с текстом скрипта
- [ ] Установка заменяет файл → снимок хранит старый → `rollback` возвращает прежнее содержимое и удаляет добавленное; список снимков с датой и источником
- [ ] Установка прервана посреди (имитация сбоя после записи части файлов) - `recover()` откатывает по снимку и возвращает строку «установка <имя> прервана - откатил»; половины набора не остаётся
- [ ] «Только в проект»: файлы в папке проекта, не в индексе git, пути возвращены результатом для `Project.copy_files`; результат несёт признак «не закоммичены»
- [ ] `set_secret`/`env_vars`: значение лежит в связке (в тесте - подменяемое хранилище) или в файле 0600 с предупреждением, в `kit.json`/логах/`state.json` его нет; `env_vars` отдаёт пары для `Run.extra_env`
- [ ] `check_update` у набора из репозитория показывает «что изменится» и ничего не ставит; изменённый хук приходит выключенным
- [ ] Тест на шве 4: `cargo test -p nightshift-core --test 'kits*'` на временном домашнем каталоге и временном каталоге данных зелёный; в тестах нет обращений к сети и к настоящему `~`
