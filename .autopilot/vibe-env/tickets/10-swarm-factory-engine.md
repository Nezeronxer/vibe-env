## Что должно заработать

Над готовым конвейером ролей (09) появляются две вещи: рой - несколько агентов одной среды на одной задаче - и фабрика - производство всей среды с Координатором и Надзирателем. Это не второй движок, а надстройка над теми же задачами и состояниями (§24); все правила отбора и подсчёта - детерминированные чистые функции в `core::swarm`, а модели только предлагают.

**Рой (галочка у поля ввода; 2-5 агентов, по умолчанию 3; смешанного роя из разных сред нет - только модели одной среды, G22.2).** Рой занимает N мест среды; если мест меньше, варианты ждут (на дорожке «в очереди»), число вне 2-5 не принимается (G11.7).
- *Соревнование (Race).* Общая подготовка (план, критик, тесты) - один раз; затем N исполнителей, каждый отдельным запуском в своей копии от ветки подготовки, модели вариантов по умолчанию - по кругу из моделей среды, начиная с модели исполнителя (`assign_models`). Ворота у каждого варианта. Ревьюер (отдельный запуск, только чтение) сравнивает прошедших, ставит балл по четырём критериям - Корректность, Покрытие, Простота, Риск - и рекомендует; `rank` упорядочивает. Человек берёт вариант (`pick_variant`); нет ответа за `autopick_min` минут (по умолчанию 10) - берётся рекомендованный. Совет ревьюера звучит без звука: это не «нужен ты». Упал один вариант - остальные идут, у упавшего «Не прошёл» с причиной; не прошёл никто - «Не вышло» с лучшей попыткой (`best_failed`: больше всего зелёных тестов) и кнопками «Взять модель сильнее / Дать подсказку / Отложить» (G15.1). Рекомендованный и выбранный варианты вливаются дальше обычной очередью слияния.
- *Бригада (Crew).* Координатор (отдельный запуск) делит задачу на части с непересекающимися файлами (JSON). Приложение проверяет пересечение само, не веря на слово (`check_split`); пересекаются - Координатор делит заново один раз, снова пересекаются - части идут по очереди. Рабочие - каждый в своей копии от ветки задачи; готовые части вливаются в ветку задачи по одной той же очередью слияния (ребейз + Ворота, `ff_branch`), затем вся задача - Ворота, ревью, влив в main.
- *Совет (Council).* N проверяющих независимо предлагают подход (только чтение); один круг: каждый видит чужие предложения и голосует; подсчёт голосов - в приложении (`tally`); пишет один исполнитель по победившему; на ревью тот же совет голосует, решает большинство, ничья - Ревьюер. Предложения и голоса сохраняются для «Обсуждения».
- *Чат роя (G11.4).* Общий чат роя - это лента событий самой задачи: события лога несут роль, модель и вариант (поля `LogEvent` из 08), поэтому лента показывает сообщения всех агентов с подписью варианта и модели. Сообщения человека роя идут через `note(id, to, text)`: `to` - «Всем», вариант (A, B, C…) или «Ревьюеру»; сообщение получит следующий запуск адресата, доставка отмечается в ленте. Отдельной сущности `Chat` у роя нет: чат-список (11) строит запись роя из задач с `Task.swarm`, а данные для панели «Гонка» (подготовка, дорожка на вариант со своей моделью, «Выбор», «сейчас»; балл, тесты, «Почему такой балл», стоимость варианта, где среда её сообщает) - это `Task.runs`, `Task.steps` и события лога.
- `stop_swarm(id)` гасит все запуски роя, не теряя готового: прошедший Ворота вариант можно взять, копии вариантов живут до «Удалить» (G11.5). Бюджет задачи - на весь рой (G11.9).

**Фабрика среды.** Свой набор задач у каждой среды; всё, что здесь запускается, - запуски только её CLI.
- *Поручение (`submit_convoy(project_id, env, text)`).* Координатор разбивает фразу на задачи (JSON: заголовок, текст, от чего зависит; не больше 12). Создаётся чат `Chat { convoy: true }` «Поручение: <фраза>» с карточками задач (`ChatMsg.task_id`) и общим идентификатором `convoy_id`; зависимая задача стартует после вливания той, от которой зависит (`depends_on`); неясное поручение Координатор уточняет вопросом по общему правилу `NEEDS_HUMAN`. Общий прогресс «3 из 5» выводится интерфейсом из задач с одним `convoy_id`.
- *Надзиратель (G08.2).* Таймер тишины по времени последнего события лога роли (`stall_min`, по умолчанию 15 минут): запуск останавливается и продолжается той же сессией с «продолжи; если застрял - скажи, что мешает»; в ленте строка Надзирателя с коротким диагнозом - отдельный запуск его модели по хвосту лога, и только при зависании (в простое токены не тратятся). Ещё 5 минут тишины - перезапуск роли новой сессией, это засчитывается попыткой; попытки кончились - «Не вышло». Ручные действия те же: `nudge(id)` («Подтолкнуть») и `switch_model` («Сменить модель» - перезапуск роли на другой модели той же среды); нажимать их не обязательно.
- *Отложить (G08.3).* Ответ роли, заканчивающийся `DEFERRED: <причина>`, возвращает задачу в очередь до следующего вливания в этот проект (`StartWhen::AfterMerge`, не больше 2 раз, потом «Не вышло» с причиной); без звука; в ленте «отложил: <причина>».
- *Очередь слияния (G08.4).* Это та же одна очередь на проект (мьютекс вливания из 03): ребейз → (конфликт → Интегратор) → Ворота → продвижение main. Для интерфейса порядок читается из шагов задач (`Merge`: идёт / ждёт, в порядке постановки в очередь) - время постановки в очередь записывается в шаге, и первая задача в трубе отличима от ждущих.
- *Заморозка (G08.7).* `freeze(true)` из 09 действует и на запуски роя, Координатора и Надзирателя: они гасятся, таймер тишины на время заморозки не тикает, рой и поручения продолжаются с того же места после `freeze(false)`.
