## Задача

Я хочу поручать работу над кодом агентам и не сидеть рядом. Сейчас агент в терминале
останавливается на каждом разрешении, ждёт, пока я проверю результат, и молчит, когда
упёрся. Если запустить несколько, они мешают друг другу в одной папке, а я не знаю, кто
закончил, кто сломал, кто ждёт меня. Проверять каждый шаг - это и есть та работа,
которую я хотел отдать.

После первого макета стало видно ещё три вещи. Всё было намешано в одном экране: Claude, Codex и
Gemini вперемешку, роли, дорожки, вкладки - глаза разбегаются. Непонятно, где просто поговорить с
моделью. И нельзя выбрать модель и её версию, а я хочу знать, какая модель что делает, и видеть,
сколько лимита подписки осталось, прежде чем запускать ещё. Плюс у меня годами настроенные скиллы,
правила и хуки - не хочу настраивать заново, и хочу отдать свою среду другому человеку.

## Решение

Приложение для macOS и Linux. Слева - мои агентские среды с их настоящими значками: Claude Code,
Codex, Gemini, opencode, Cursor, Qwen, своя команда. Я «вхожу» в среду, и всё внутри - только её:
чат с её моделью, её задачи, её фабрика, её настройки, её лимиты. Среды друг с другом не смешиваются.

Внутри среды главное - чат. Спрашиваю модель про проект - она отвечает. Пишу «Сделай…» - это
становится задачей прямо в той же ленте: приложение само переписывает мои слова в нормальный промпт
под выбранную модель, и дальше агенты работают сами. Каждая роль (планировщик, критик плана, автор
тестов, исполнитель, ревьюер, интегратор) - отдельный запуск той же среды, с моделью, которую я
назначил ей (или с той, что по умолчанию). Работа идёт в отдельной копии репозитория, проверяется
тестами и независимым ревьюером и вливается одним коммитом в main. Над лентой - тихие полоски
лимитов этой среды (например, 5 часов и неделя у Claude).

Меня зовут (системным уведомлением со звуком и пометкой на значке среды) в трёх случаях: агенту
нужно решение, которое может принять только я; задача не вышла после всех попыток; нужно разрешение
отправить код наружу (push / PR). Галочка «Качество» включает конвейер приёмов, которые советуют
Anthropic и сообщество; галочка «Рой» ставит на одну задачу несколько агентов. Фабрика показывает
всё производство среды: кто работает, кто завис, что в очереди слияния. Наборы переносят скиллы,
правила, хуки, MCP и субагентов между машинами и людьми - секреты и опасные хуки не переезжают сами.
Любую готовую задачу можно откатить одной кнопкой; всех агентов можно заморозить одной клавишей.

## Словарь

- **Среда** - агентская CLI на этом компьютере (Claude Code, Codex, Gemini CLI, opencode, Cursor CLI,
  Qwen Code, своя команда). Замкнутый мир: всё, что запускается внутри, запускается её CLI.
- **Модель** - семейство моделей среды (Opus, Sonnet; GPT-Codex; Gemini Pro…). **Версия** - номер
  модели; «последняя» - сама переходит на новую, закреплённая - стоит на номере.
- **Чат** - переписка с моделью среды по одному проекту. В нём живут задачи, поставленные из него.
- **Задача** - то, что поставил человек: текст + проект + среда. Одна задача - одна ветка - один
  итоговый коммит.
- **Проект** - папка с git-репозиторием, добавленная в приложение. Проект общий для всех сред.
- **Роль** - что делает агент в задаче: Планировщик, Критик плана, Автор тестов, Исполнитель,
  Ревьюер, Проверяющий, Интегратор; в рое и на фабрике ещё Координатор, Надзиратель.
  **Ворота** и **Очередь слияния** - не агенты, а команды и порядок приложения.
- **Запуск** - один вызов CLI среды с одной ролью и своей сессией.
- **Шаги качества** - конвейер: план, (спека), критик, тесты сначала, код, Ворота, (e2e), ревью, влив.
- **Рой** - несколько агентов одной среды на одной задаче (Соревнование, Бригада, Совет).
- **Фабрика** - все задачи и агенты одной среды разом: состав ролей, дорожки, очередь слияния, лента.
- **Поручение** - фраза на фабрике, которую Координатор разбивает на задачи (группа с общим прогрессом).
- **Набор** - экспорт скиллов, правил, хуков, MCP, субагентов и настроек одной среды; **снимок** -
  копия того, что набор заменил, для отката.
- **Лимит** - окно расхода подписки среды (5 часов, неделя, день…): процент и время сброса.
- **Финиш** - что происходит с готовой задачей: влить локально / влить и запушить / PR.
- **Наружу** - любое действие, которое видно вне машины: push, PR.
- **Нужен ты** - три повода позвать человека: вопрос, «Не вышло», разрешение наружу. Янтарный цвет
  в интерфейсе - только у них.

Решения по реализации v3 (craft, не спрашивались):
- **Событие действия** - новый вариант `AgentEvent::Action(ToolAction)` с `ToolAction {id, name, input: ActionInput, output: Option<String>, ok: bool, done: bool}`, `ActionInput = Read{path} | Edit{path, diff} | Write{path, head, lines} | Bash{command} | Search{pattern, hits} | Web{target} | Plan{items: [{text, state: pending|active|done|dropped}]} | Other{summary}`; дифф - унифицированный текст, строится в ядре (крейт `similar`, разрешён) из `old_string/new_string`, для CLI без текста правки - `git diff` копии после шага. Вывод инструмента связывается с действием по `tool_use_id`. Частичный текст - `AgentEvent::TextDelta(String)`. Старые `Tool{name, summary}` остаются для совместимости и в лог пишутся как раньше.
- **В окно** - события `task-action` и `chat-action` `{id, action}` и `chat-delta` `{id, msgId, text}`; поток в окно склеивается не чаще раза в 50 мс на вкладку (иначе окно тормозит на быстром выводе).
- **Разметка** - своя в `ui/js/core/md.js` (без библиотек и без `innerHTML`: узлы через `h()`), подсветка - `ui/js/core/hl.js`, регулярные токены на язык.
- **Вкладки** - чисто интерфейс (`ui/js/screens/tabs.js` + состояние в `localStorage` и копия в настройках `ui.tabs` через существующую команду настроек); ядру нового не нужно, кроме того, что чаты уже параллельны.
- **Гонка «файл изменился на диске»** из живого прогона - причина не доказана; таск ядра воспроизводит на живом CLI и чинит, если это наша гонка (шаг «тесты сначала» и исполнитель, сторож), или записывает, что это поведение CLI.

### v4: эмулятор терминала, моды и каталоги, автообновление, GitHub, Clawd (G33-G50)

Источник - `2026-10-23-brief.md`. Вопросы брифинга пользователь отклонил («продолжи Автопилот, но внедри
туда всё») - развилки решены как ASSUMPTION в манифесте и перечислены в отчёте. Ролики YouTube (G53) разобраны
скиллом frameproof с расшифровкой речи (`research-youtube.md`). «Субтитры создавал DimaTorzok» в третьем сообщении -
артефакт распознавания речи, не требование. Правило «проверять через computer use все новые приложения» (G59)
для Nightshift - история 304, для будущих приложений - память пользователя `test-new-apps-via-computer-use`.

**Решение v4.** Nightshift становится агентным эмулятором терминала. Всё на экране - панели на тёмном
холсте (светлая тема остаётся): скруглённые карточки с зазором между ними. Панель - либо **терминал**
(настоящий shell или CLI среды в PTY), либо **сессия агента** (лента v3, теперь свёрстанная как вывод
терминала: строка-приглашение `❯`, блоки команд с выводом, диффы). Хрома три полосы: вкладки сверху
(с Clawd в углу), строка состояния снизу (среда · модель · ветка · лимиты), скрываемая боковая панель
чатов. Всё остальное - через палитру команд ⌘K. Каталог ставит скиллы, MCP и моды из популярных
источников в текущую среду; CLI сред и списки моделей обновляются сами; проект публикуется на GitHub
и показывает красивую историю коммитов.

#### Clawd - история (G47)

> **ru.** Clawd родился пикселем на заставке Claude Code - девять точек в ширину, пять в высоту. Днём
> он сидел смирно, пока люди печатали команды. А ночью, когда все уходили спать, он замечал, что
> терминалы не гаснут: агенты продолжали работать, и никто не смотрел, как у них дела. Тогда Clawd
> взял на себя ночную смену. Он бегает между вкладками, стучит лапками вместе с теми, кто пишет код,
> подпрыгивает, когда задача уходит в main, и машет, если без тебя никак. Говорят, он ни разу не
> спал на дежурстве - только когда ты сам ставишь всё на паузу.
>
> **en.** Clawd was born as a pixel on the Claude Code splash screen - nine dots wide, five tall. By
> day he sat still while people typed. At night, when everyone went to bed, he noticed the terminals
> stayed on: agents kept working and nobody watched over them. So Clawd took the night shift. He runs
> between tabs, taps along with whoever is writing code, jumps when a task lands in main, and waves
> when it cannot go on without you. They say he has never slept on duty - only when you pause
> everything yourself.

#### Решения по реализации v4

- **PTY в ядре** (`core::term`), не в `app`: сессии переживают окно (260), тестируются без Tauri (ADR 0001).
  Крейт `portable-pty` 0.9 (MIT; проба на этой машине: чтение, запись, resize работают). Кольцевой буфер 2 МБ на
  сессию для досылки в новое окно и восстановления (253).
- **Вывод в окно** - `tauri::ipc::Channel<InvokeResponseBody>` с `Raw` (в JS приходит `ArrayBuffer`), не `emit` и не
  `Channel<Vec<u8>>` (уйдёт JSON-массивом); склейка кусков ~4 мс, байты без перевода в строку, подтверждение записи
  от окна раз в ~100 КБ (flow control xterm) - ядро притормаживает чтение, пока окно не догнало.
- **Эмулятор в окне** - `@xterm/xterm` 6.0.0 + аддоны fit 0.11.0, webgl 0.19.0, search 0.16.0, unicode11 0.9.0,
  web-links 0.12.0 файлами `lib/*.js` в `ui/vendor/xterm/` без сборщика; MIT - `ui/vendor/xterm/LICENSE`. В 6.0
  нет canvas-рендерера: WebGL, запасной - DOM. CSP: xterm пишет `<style>` - если WKWebView требует, `style-src`
  получает `'unsafe-inline'` (только стили, не скрипты), с записью в `docs/security.md`.
- **Сначала замер** (первый таск терминала): 10 000 строк `yes`/`cat` большого файла в PTY-вкладке release-сборки -
  без потери вывода и с откликом ввода ≤ 50 мс; не проходит - стоп и решение до интерфейса (риск: cmux ушёл с Tauri
  из-за скорости). Прозрачность окна - без `macOSPrivateApi`: прозрачность панелей внутри окна, не окна целиком.
- **Сеть ядра** - системный `curl` через `Command` (как `git`/`gh`): без новой зависимости и TLS-стека; лимит размера
  и тайм-аут на вызов; за шов `trait Fetch` для тестов. Нет `curl` - ключ `curl_missing`.
- **Каталог** - `core::market`: источники за `trait Source`, установка - через `core::kits` (новые единицы: мод,
  скилл-папка, MCP-сервер), значит те же снимки, выключенное исполняемое и запрет секретов в файлах.
  Встроенные источники (проверены живым запросом без ключа, `research-catalogs.md`): скиллы - `skills.sh/api/search`,
  маркетплейсы `marketplace.json` (anthropics/skills, anthropics/claude-plugins-official, claude-plugins-community),
  запасной `skillsmp.com/api/v1/skills/search`; MCP - официальный реестр `registry.modelcontextprotocol.io/v0.1/servers`
  (`limit=10`, пагинация `metadata.nextCursor`), `api.mcp.github.com/v0.1/servers`, `registry.smithery.ai/servers`
  (условия Smithery сверить до включения по умолчанию); моды - отдельного каталога нет: git-репозитории с
  `marketplace.json` и образцы `anthropics/claude-code-playground`. Мод - плагин с `hooks/hooks.json {"modules":[…]}`.
  Пути скиллов: Claude `~/.claude/skills`, Codex `~/.agents/skills`, Gemini `~/.gemini/skills`.
- **Дыра наборов (D05-кандидат, чинится в таске каталога):** `kits::SCRIPT_EXT` не знает `tsx`/`jsx` - мод вида
  `clawd-run` (`hooks/register.tsx`) не помечается исполняемым; добавляются `ts`, `tsx`, `jsx`, `mjs`, `cjs`.
- **Обновления** - `core::updates`: версии, способ установки, команда обновления, откат; расписание - в `app`.
- **GitHub** - `core::git`: `publish`, `log_page` (страница коммитов с графом); всё через `git`/`gh`.
- **Интерфейс v4** - тот же ванильный JS. Раскладка - дерево панелей (`split{dir, ratio, a, b}` | `pane{kind, …}`),
  сохраняется в `Settings.ui.tabs` (v3). Тема - CSS-переменные из одной таблицы, её же получает xterm. Clawd -
  `<canvas>` с пиксельной сеткой, один цикл `requestAnimationFrame` на окно.
- **Окна** - Tauri `WebviewWindow` с тем же `index.html?window=<id>`; вкладка переносится описанием (вид панели,
  id PTY-сессии или чата), процессы остаются в ядре.

#### Решения по реализации v6

- **Очередь чата - в ядре** (`core::chat`): `Chat.queue: Vec<QueuedMsg{id, text, attachments, at}>` и `Chat.wait: Option<Wait{resets_at, msg_id}>` в `state.json` (через `Store`); при `Chats::new` - восстановление ожиданий и поиск неотвеченных по `reply_to`. UI становится отображением ядра. Почему: только ядро переживает перезапуск окна и приложения.
- **Пауза полосы роя** - `LaneState::Paused{resume_at}`; задача в `PausedLimit` только если все живые полосы на паузе. Почему: так рой не теряет работающих агентов.
- **Вложения** - `<data>/attachments/<chat>/`, в `Run` - список путей; адаптер Claude дописывает в промпт строку с путями (CLI читает картинку инструментом Read по пути - сверить в research-v6); у других сред - флаг `supports_images()` по документации, по умолчанию false. Перетаскивание на поле ввода гасит глобальный drop «открыть папку».
- **Issues** - в `core::suggest` источник `Issue{number, url, title}` рядом с TODO; `gh issue list --json number,title,url,labels --state open --limit 30`; закрытие - через вопрос человеку тем же механизмом, что `Auto::look`/`ask_push`.
- **Сессии из терминала** - новый модуль `core::sessions`: ключ проекта Claude Code (путь с `/` → `-`, сверить по живым каталогам `~/.claude/projects`), чтение заголовков jsonl, продолжение через задачу с `resume_session`.
- **Версия и обновления приложения** - `Settings.release_feed: Option<String>` (по умолчанию None, пока репозиторий не опубликован; в публичной копии - URL `releases/latest` GitHub API), проверка через существующий `core::net`.
- **Расходы** - `spend_history.json`: `{day, project, env, usd, tokens_in, tokens_out}`; запись в тех же местах, где сейчас `day_spend`.
- **Отчёт об ошибке** - `core::diag::collect(dir, out) -> PathBuf` по белому списку; `zip` уже в зависимостях; скраб - `kits::scrub` выносится в общий `core::scrub` (kits продолжает им пользоваться).
- **Мысли и плавность** - `AgentEvent::Thinking(String)`, `ChatEvent::Thinking{chat,msg_id,text}`, событие окна `chat-thinking`; `Coalescer` склеивает по ключу (msg_id, kind). Раскрытие текста - один rAF-цикл на ленту (`ui/js/core/reveal.js`), узел потока дописывается.
- **Слова модов** - `agent::Adapter::ui_hints(cwd) -> UiHints{spinner_verbs: Vec<String>, …}`: Claude читает `~/.claude/settings.json` и `.claude/settings*.json` проекта (только текстовые ключи); для остальных - пусто.
- **Меню «/» и «В терминале»** - `Adapter::inventory(cwd) -> Inventory{skills, commands, mcp, mods}` (на основе `kits_inventory`) и `Adapter::resume_argv(session, cwd) -> Option<Vec<String>>`; вкладка-терминал - существующий `NS.term.open` (v4); возврат в чат - дочитывание jsonl сессии (Claude) или пометка «не умеет».
- **Чистая сборка** - мок/тест-файлы уходят из `ui/` в `ui-dev/` (или релизный `frontendDist` собирается копией без них - выбрать в таске по тому, что проще поддержать с selftest); `[profile.release] strip = true` и `--remap-path-prefix` в `.cargo/config.toml`; copyright «Nightshift contributors».
- **Окружение запусков** - `NIGHTSHIFT_PROJECT`, `NIGHTSHIFT_PROJECT_NAME` в `Run.extra_env` всех ролей и чата.

## Решения по реализации

1. **Tauri 2 + Rust, интерфейс - обычные HTML/CSS/JS без фреймворка и без сборщика.** Одно приложение на обе ОС, лёгкое, уведомления/трей/клавиши - готовые плагины Tauri. Утверждённый макет уже написан на чистом JS (≈650 строк на 10 экранов) - фреймворк его не упростит.
2. **Ядро - отдельная Rust-библиотека `core` без зависимости от Tauri.** Весь цикл задачи, чат, рой и фабрика тестируются без окна: фейковый агент + временный git-репозиторий.
3. **Агент - внешний CLI-процесс**, вывод читается построчно (stream-json / JSONL) и переводится в общие события. Сессия продолжается флагом продолжения среды (Claude `--resume`, Codex `exec resume`, Gemini/Qwen `--resume`, opencode `-s`, Cursor `--resume` `[CLI-факт: research-clis §1-6]`) - так ответ человека, заметки и исправления после Ворот/ревью идут в тот же контекст роли.
4. **Сигналы агента - строки в конце ответа**, а не MCP-сервер: `NEEDS_HUMAN:` (+ `OPTIONS:`), `DEFERRED:`, в чате `NS_TASK:`. Работает с любой средой, ноль кода на протоколы. Правила - в системной добавке (у Claude `--append-system-prompt`, у остальных - в тексте промпта).
5. **Права ролей.** Пишущие роли: «автономный» режим среды (Claude `--permission-mode bypassPermissions` + `--settings` с запретами `Bash(git push:*)`, `Bash(git remote:*)`, `Bash(sudo:*)` и песочницей, где версия её поддерживает; у остальных - флаги автоприёма, уже выбранные в адаптерах таска 02: Gemini `--approval-mode=yolo`, Cursor `-f`, opencode `--auto` `[CLI-факт: research-clis §3-5]`; Codex - `-a never` в его песочнице с записью в рабочую копию `[CLI-факт: только документация, §2]`; Qwen - как в адаптере таска 02, проверен живьём). Роли только для чтения - флагом чтения среды (история 133), где его нет - в выбрасываемой копии. Грабля из опыта: deny-правила `Read(...)` у Claude превращаются в запрет ОС в песочнице - не запрещать `*.pem` и `.env` (ломаются TLS и тесты), только `~/.ssh`.
6. **Структурированные ответы ролей** (разбор Планировщика, вердикт ревьюера, план Координатора, голос совета, ответ Проверяющего) - строго JSON. Где среда умеет схему - передаётся схема (Claude `--json-schema`, Codex `--output-schema` `[CLI-факт]`), иначе JSON ищется в тексте. Невалидный ответ → один повтор, затем шаг неудачный (ревьюер - «changes» с пометкой «ответил не по формату», как в v1).
7. **Коммиты делает приложение, не агент:** после хода пишущей роли `git add -A && git commit` в её копии (если есть изменения), с проверкой защищённых путей (218). Финиш - squash: один коммит на main через `git commit-tree` от дерева перебазированной ветки. Откат = `git revert <sha>`.
8. **Продвижение main без порчи рабочей копии человека:** если основная копия стоит на main и чистая → `git merge --ff-only`; если на main и грязная → ждать (история 22); если на другой ветке → `git update-ref refs/heads/main <new> <old>` (атомарно, только вперёд).
9. **Вливание - одна очередь на проект** (мьютекс): перебазирование → (конфликт → Интегратор) → Ворота → продвижение main. Ревью после чистого rebase не повторяется, только Ворота.
10. **Хранилище - JSON-файлы** в каталоге данных приложения (`~/Library/Application Support/nightshift` / `~/.local/share/nightshift`): `state.json` (проекты, настройки, задачи, чаты), `logs/<task>.jsonl`, `chats/<chat>.jsonl`, `catalog.json` (снимок моделей), `limits.json` (последние окна лимитов); запись через временный файл + rename. Объёмы - сотни задач и чатов, база не нужна. Новые поля - с умолчанием при чтении, файл v1 читается без миграции.
11. **Секреты наборов - в системной связке ключей** (`keyring`: Keychain / Secret Service, служба `nightshift`, имя = `<среда>/<переменная>`); без связки - файл 0600 и предупреждение. В `state.json`, логах, наборах и файлах CLI значений нет. (В v1 здесь был токен Telegram - снят, G03.) **Имена переменных из набора - по запрету классами** (D04, ремонт ветки 22.10: ревью показало, что набор через `SHELL`, `ZDOTDIR`, `GIT_CONFIG_*`, `PYTHONPATH`, `*_BASE_URL`, прокси запускает код или уводит ключ): `kits::env_name_allowed` отклоняет точные имена (PATH, HOME, SHELL, ZDOTDIR, EDITOR …), префиксы (GIT_, SSH_, LD_, DYLD_, PYTHON, PERL, RUBY, NODE_, SSL_ …) и суффиксы (_HOME, _PATH, _PROXY, _BASE_URL, _OPTIONS …) без учёта регистра; значение - без CR/LF/NUL. **F1 (аудит 22.10):** поверх классов - разрешительный список: из набора задаётся только имя, оканчивающееся на `_KEY|_TOKEN|_SECRET|_PASSWORD`; классы остаются вторым барьером. Настройки набора - так же: без галочки только ключи из `Layout.safe_settings` среды.
12. **Оповещения - только системные уведомления и окно** (G03 снят): `Notifier` получает те же `Notice`; тихие часы, звук и склейка зовов (183) - в уведомителе приложения, ядро о них не знает.
13. **GitHub - через системные `git` и `gh`**: авторизация та, что уже настроена у человека. Своих OAuth и токенов GitHub приложение не хранит.
14. **Лимит подписки** распознаётся адаптером: у Claude - `rate_limit_event` со статусом не «allowed» и ошибка категории `rate_limit` `[CLI-факт: «Проверено живым запуском»]`; у остальных - по тексту (`usage limit`, `limit reached`, `quota`, `resets …`) `[CLI-факт: не подтв.]`; время сброса - из события или текста, иначе +30 мин. Gemini может включить свой fallback-маршрут с запросом согласия `[CLI-факт: research-clis §3]` - в неинтерактивном запуске это проверяется в таске адаптера, чтобы запрос не повесил процесс.
15. **Среда - замкнутый мир (G17, G22).** Среда = id адаптера (`claude`, `codex`, `gemini`, `opencode`, `cursor`, `qwen`, `custom:<id>`); `Task.agent` уже хранит её, и все запуски задачи берут этот адаптер. Поля проекта v1 `reviewer` и `fallback_agent` остаются в файле ради чтения старых данных, но движок их не читает (история 80). Почему: так смешать среды невозможно технически, а не только запретом в интерфейсе.
16. **Роль = отдельный запуск.** У каждой роли своя сессия, своя модель, свой промпт. Модели ролей задачи - снимок настроек среды в момент создания задачи; «последняя» превращается в номер при старте запуска (88). Почему: задача воспроизводима, а смена настроек не ломает идущее.
17. **Шаги - не новые статусы.** `Status` из v1 не меняется (UI-группы и тесты на нём), кроме одного нового `HandedOff` (A07). Положение внутри конвейера - список шагов задачи с состоянием. Почему: машина состояний v1 проверена 31 e2e-тестом, шаги качества живут внутри её `working`/`checking`/`reviewing`.
18. **Промпт под модель (G14) - два слоя.** Планировщик (отдельный запуск только для чтения, в копии на свежей main) отдаёт разбор: цель, ограничения, «готово, когда», файлы, расплывчата / в одну фразу / рискованна, план. Приложение собирает промпт исполнителя детерминированно по шаблону вендора модели исполнителя (почему: правило вендора проверяемо тестом, а не зависит от настроения модели), мои слова дословно - отдельным блоком (148), чужие данные - в метках (151). Шаблоны вендоров - по их официальным руководствам по промптам; ссылки собираются в таске промпта `[CLI-факт: не подтв.]`.
19. **Чат (G20) - отдельный модуль поверх движка.** Чат = среда + проект + сессия CLI. Каждое сообщение - запуск роли «Чат» только для чтения в копии чата (worktree на свежей main без ветки, обновляется перед сообщением; изменения выбрасываются). Задача распознаётся двумя слоями: первый глагол из словаря (быстро, предсказуемо, как подсказывает макет) и признак `NS_TASK:` от модели (ловит остальное); ошибка исправляется «это был вопрос» (107). Почему не всегда спрашивать модель: лишний запуск на каждое «сделай» и задержка.
20. **Заметки человека** (сообщения во время задачи, сообщения рою) хранятся рядом с состоянием «между ходами» задачи (как ответ человека в v1) и уходят в следующий запуск адресата; доставка отмечается в ленте. Почему: в неинтерактивную CLI нельзя дописать в идущий процесс.
21. **Каталог моделей (G18, G23).** Источник по среде: Codex `codex debug models`, opencode `opencode models [provider]`, Cursor `--list-models` (разбор вывода - в адаптере на образцах); Claude, Gemini, Qwen - встроенный список-подсказка (семейства, версии, порядок «от сильной к быстрой», описания; обновляется с выходом приложения) `[CLI-факт: research-clis, сводка]`; везде - «Своя модель» и «Как в CLI по умолчанию» (без флага). «Последняя» у Claude = алиас семейства (`opus`, `sonnet`, `fable` - «alias for the latest model» `[CLI-факт: research-clis §1]`), у остальных - первая версия семейства в списке. Снимок списка - на диске; снятая версия = пропала из списка или отвергнута CLI. Флаг модели: Claude `--model`, Codex `-m`, Gemini `-m`, opencode `-m provider/model`, Cursor `--model`, Qwen `-m` `[CLI-факт]`.
22. **Лимиты (G26) - общая запись, данные только от среды.** Окно: название, модель (если окно по модели), процент или остаток, время сброса, источник, «на когда». Адаптер выдаёт окна из событий запуска (Claude - `rate_limit_event.rate_limit_info.unifiedWindows.{five_hour, seven_day}.{utilization, resetsAt}` в каждом запуске `[CLI-факт: «Проверено живым запуском»]`) и из сообщения о лимите (исчерпан + сброс). Своих оценок приложение не делает: у сред без данных - «нет данных» (98). Движок хранит последнее значение на среду (`limits.json`) и использует «исчерпан» для паузы, запасной модели и ночной очереди. Почему: выдуманный процент хуже честного «нет данных» - по нему примут неверное решение.
23. **Рой (G11).** Соревнование - N копий от одной ветки подготовки, Ворота у каждой, ревьюер сравнивает (JSON: балл по 4 критериям, совет), автовыбор по таймеру. Бригада - Координатор отдаёт части с непересекающимися файлами; приложение проверяет пересечение само (не верит на слово), части вливаются в ветку задачи той же очередью слияния, что и main. Совет - N запусков только для чтения, один круг голосования, подсчёт голосов - в приложении. Почему: правила отбора и подсчёта - детерминированные функции, проверяемые тестом; модели только предлагают.
24. **Фабрика (G08) - не отдельный движок**, а вид на задачи среды + две функции движка: Надзиратель (таймер тишины по последнему событию лога; диагноз - короткий запуск его модели только при зависании, в простое токенов не тратит) и поручения (Координатор → задачи с зависимостями). Почему: состояние задач уже в движке; второй планировщик был бы второй правдой. Из Gas Town не переносим Мэра отдельным агентом, Deacon/Dogs/Boot, почту, федерацию (research-factory.md).
25. **Заморозка вместо паузы в интерфейсе.** «Заморозить всё» гасит процессы агентов сразу (группой процессов), статусы и сессии сохраняются, вливание в git не прерывается (66). Мягкая пауза v1 (`pause_all`: дойти до конца шага) остаётся в движке и используется ночной очередью; в интерфейсе одна кнопка - меньше понятий (G19).

27. **Присутствие, сон, Wayland - в `app`.** Простой и блокировка экрана (macOS - системный счётчик простоя; Linux - через idle-сервис композитора, где он есть, иначе только ночное окно), запрет сна (macOS - power assertion, Linux - `systemd-inhibit`), один экземпляр и флаг `--new-chat` - платформенный код окна; ядро получает только «человек здесь / нет». 28. **«Продолжить в терминале» (A07)** - адаптер отдаёт интерактивную команду продолжения сессии (или ничего); `app` открывает системный терминал (macOS - Terminal через `open -a`; Linux - `$TERMINAL`, иначе первый найденный из списка) с аргументами списком, без склейки в строку оболочки. ### Машина состояний задачи (v1 + v2)

```
queued(start: now | night | after_merge) → preparing → working → checking → reviewing → merging → done
working   = шаги: plan [→ spec] → critique → tests_first → code        (пропущенные - Skipped)
checking  = Ворота [→ e2e];      провал → working (≤ потолок попыток), иначе failed
reviewing = вердикт;             changes → working (≤ кругов), иначе failed
            рой «Соревнование»: сравнение → выбор (человек или таймер) → merging
merging   = rebase → (конфликт → Интегратор) → Ворота → продвижение main
            ├→ awaiting_outward (Запушить | Push и PR | Только push | Не надо) → done | done_not_pushed
            ├→ merge_blocked (грязная main) → merging
            └→ done_not_pushed (push не вышел) → retry (PR-проект) | push_base (Push-проект) → done
working | checking | reviewing ⇄ needs_human
working | checking | reviewing → paused_limit → (сброс | запасная модель) → тот же шаг
working (DEFERRED) → queued(after_merge, ≤ 2)
working | checking | reviewing | needs_human | failed → handed_off (A07) → checking («Вернуть агентам»)
failed → (подсказка | другая модель) → working (та же копия, попытки заново)
любой → failed · любой → cancelled · done → reverted
D01: finish=Push и «спрашивать» → done → reverted → awaiting_outward (push_revert) → reverted;
     файл из copy_files / защищённый путь, закоммиченный агентом, вырезается до вливания; не вырезался → failed: hidden_file_committed;
     у PR-задачи отката нет: pr_no_undo
Заморозка - не статус: флаг движка, запуски погашены, статусы сохранены (§25).
```

## Аудит безопасности (G04)

Когда: после сборки, перед приёмкой. Как: Workflow из независимых проверяющих; каждая находка уходит
на перепроверку свежему агенту без контекста первого; подтверждённое чинится, неподтверждённое и
отложенное - в отчёт с причиной. Профильные скиллы `cybersecurity-skills` проверяющие читают из папки
плагина (`SKILL.md`), плагин не включается. Признак готовности - отчёт с каждой находкой и её судьбой;
проверка с моей стороны - команды, перечисленные в отчёте, запускаю сам.

| Область | Что проверяется |
|---|---|
| `/security-review` | весь дифф v1 + v2 |
| Секреты | gitleaks по дереву и всей истории; нет значений в `state.json`, логах, наборах, промптах; связка ключей и файл 0600 |
| Инъекции в команды | ни одного `sh -c` со вставкой данных: своя команда - позиционные параметры (тест `$(touch PWNED)` из таска 02), «Дополнительные аргументы» - список, терминал A07 - аргументы списком, id сессии по формату; ссылка набора - только разрешённые схемы, без `ext::` и `--upload-pack` |
| Инъекции в промпты | текст задачи, файлы, дифф, вывод, чужие наборы - в метках «данные»; сигналы (`NEEDS_HUMAN`, `DEFERRED`, `NS_TASK`) принимаются только из конца собственного ответа роли; скиллы из импортированного набора - помечены, скрипты выключены |
